# Troubleshooting

**`Error: Cannot find module 'server-only'` when running the worker**
Don't `import "server-only"` in any module reachable from
`src/server/queue/worker.ts`. That package intentionally throws when
`require`d outside Next.js's webpack build (its whole purpose is to break a
client-bundle build, not to be a runtime guard) - it works fine inside
Next.js's own build/dev server but crashes a plain `tsx`/`node` process. Only
`src/server/auth/session.ts`-adjacent, web-only code should ever consider it,
and even there this build ended up removing it in favor of a clean
worker/web module boundary (`src/server/errors.ts` has no Next dependency,
so both processes can import shared error types safely). If you see this
again after adding a new module, check what it transitively imports.

**Generation job stays QUEUED forever**
The worker process isn't running. `npm run worker` in a separate terminal/
process - the web app only enqueues jobs, it never runs the pipeline itself
(directive §120).

**`ffmpeg: command not found` from a provider or the render step**
Install ffmpeg and make sure it's on `PATH` for whichever process runs the
worker: `apt-get install -y --no-install-recommends ffmpeg` (Debian/Ubuntu).
Avoid the `recommends` set - it pulls in a full mesa/VA-API/GPU driver stack
you don't need for headless server-side encoding and which can fail to
install in a minimal container.

**Images are solid-color rectangles with text, not photos**
That's the Mock image provider - expected with no image-generation API key
configured (see PROVIDERS.md). It's not a bug; it's what lets the entire
pipeline run for free.

**Voice narration sounds like a tone, not speech**
Same reason - Mock voice provider, see PROVIDERS.md.

**`InsufficientCreditsError` / 402 on generate**
The user's `creditBalance` is lower than the estimated cost. Check
`/dashboard/billing` for their ledger history, or grant credits via
`grantCredits()` (there is no admin UI for this yet - see PRODUCT_SPEC.md
roadmap).

**Postgres/Redis not reachable in local dev**
This build was developed against a local Postgres 16 + Redis 7 (see
`DATABASE_URL`/`REDIS_URL` in `.env`). Confirm both are running:
`pg_isready` / `redis-cli ping`.

**`next-env.d.ts` keeps getting regenerated/conflicting**
That file is intentionally gitignored and regenerated by Next.js on
`next dev`/`next build` - don't hand-edit it, don't worry about diffs to it.

**Prisma client out of sync after a schema change**
Run `npm run db:generate` (or `npx prisma migrate dev` in development, which
also regenerates the client) after editing `prisma/schema.prisma`.
